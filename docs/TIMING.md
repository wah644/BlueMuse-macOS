# Timing modes

Timing behavior assigns a timestamp to each sample. It is separate from channel
values, sample precision, clock domain, LSL clock synchronization and graph rendering.

## Windows compatible (default)

For Muse 2 and other legacy models, each block uses its first-channel host arrival
time. Samples are backdated using the original float32 millisecond interval constants:

`timestamp[i] = arrival - (sample_count - i) × sample_interval`

Examples: EEG has 12 samples per block at nominal 256 Hz; motion has three at 52 Hz;
PPG has six at 64 Hz. A batch arriving early relative to the preceding batch can
produce overlapping or backwards timestamps. There is no monotonicity correction.

The Unix epoch clock reproduces the original millisecond quantization. Both LSL clock
selectors call liblsl directly, as in the supplied current Windows source.

Legacy telemetry preserves the original one-sample backdating: at nominal 0.1 Hz,
its timestamp is arrival minus ten seconds. Athena battery is stamped at arrival.
Athena's regular streams use a literal port of the original C# recursive corrector,
including its covariance formula. These behaviors are preserved for compatibility;
they are not claims of accurate physical acquisition time.

Compatibility is checked against timestamp fixtures generated by the original C#
classes. It matches timestamp-assignment rules given the same arrivals, not actual
arrival schedules on two different operating systems.

## Smoothed (opt-in)

Regular sensor streams fit sample index to host arrival time with a positive-covariance
recursive fit and enforce increasing packet boundaries. Legacy first blocks use the
same backdated anchor convention; later blocks use the fitted sample clock. Telemetry
uses arrival time directly. This reduces arrival jitter in assigned times but does not
recover a device acquisition clock or prove better alignment with external events.

## Stream lifecycle and metadata

Changes take effect at the next stream start. A session captures its timing and clock
settings, so an outlet's metadata remains consistent with its samples. The four-channel
output preserves the exact primary timestamps from that session's EEG output.

Metadata fields include `timestamp_behavior` (`WINDOWS_COMPATIBLE` or `SMOOTHED`),
`primary_timestamp_format`, and `secondary_timestamp_format`. MUSE_4CH contains four
sensor columns only, with no secondary timestamp columns.

Graphs use host display coordinates independently of published timestamps, so a
compatibility-mode overlap does not corrupt the graph's bounded display history.
Graph drawing does not modify published values or times.

Use an LSL clock when synchronizing with other LSL sources; Unix epoch values have a
different origin. Downstream LSL clock synchronization and dejitter processing may
change received timestamps. The example receiver uses `processing_flags=0` to preserve
what the outlet supplied. Event-related or other timing-sensitive work needs hardware
validation, not simply a smooth-looking plot.
